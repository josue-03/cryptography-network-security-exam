\section{Introduction}
This report documents the security assessment and technical work carried out for the ETTCS801 Integrated Situation. The scenario involves a polytechnic institute storing student records on a central server and transferring files between two campuses, with weak staff passwords, outdated software, unencrypted transfers, and guest network access to the records server identified as issues in a security review.

\section{Risk Assessment}

\subsection{Assets, Vulnerabilities and Consequences}

Inter-campus file transfer channel & Transfers are unencrypted & Interception (eavesdropping) in transit \\

\subsection{Recommended Controls}
\begin{itemize}
  \item Guest access to records server: network segmentation (VLANs) and firewall rules denying guest traffic
  \item Weak staff passwords: strong password policy plus multi-factor authentication (MFA)
  \item Unencrypted transfers: encrypt in transit (SFTP/SCP or TLS) instead of plaintext protocols
\end{itemize}

\section{Encryption and Integrity Toolkit}
The \texttt{crypto\_toolkit.py} programme was developed to encrypt and decrypt student records and to verify their integrity.

\subsection{Design}
\begin{itemize}
  \item \textbf{Encryption:} symmetric encryption using \texttt{Fernet} (AES-128 in CBC mode with HMAC authentication) from the Python \texttt{cryptography} library.
  \item \textbf{Integrity:} SHA-256 hashing via \texttt{hashlib}, with the hash saved alongside the file and re-checked on demand.
  \item \textbf{Robustness:} all file operations are wrapped in \texttt{try/except} blocks so missing files or invalid input do not crash the programme.
\end{itemize}

\subsection{Test Evidence}
\begin{lstlisting}
$ python3 crypto_toolkit.py genkey
[OK] Key generated and saved to secret.key

$ python3 crypto_toolkit.py encrypt sample_record.txt sample_record.enc
[OK] Encrypted 'sample_record.txt' -> 'sample_record.enc'

$ python3 crypto_toolkit.py hash sample_record.enc
[OK] SHA-256 of 'sample_record.enc':
     69fe15c94f975f06fc1ac371ae85c43c37346bfdbf982416ad2bc9e28992962c

$ python3 crypto_toolkit.py verify sample_record.enc sample_record.enc.sha256
[OK] Integrity check PASSED - file has not been modified.

$ python3 crypto_toolkit.py decrypt sample_record.enc sample_record.dec
[OK] Decrypted 'sample_record.enc' -> 'sample_record.dec'
$ diff sample_record.txt sample_record.dec
MATCH: decrypted file is identical to original

$ echo "tampered" >> sample_record.enc
$ python3 crypto_toolkit.py verify sample_record.enc sample_record.enc.sha256
[ALERT] Integrity check FAILED - file has been modified!
\end{lstlisting}

The final test confirms the toolkit correctly detects tampering after the encrypted file was deliberately modified.

\section{Network Traffic Filtering}
Firewall rules were applied in the authorised laboratory environment using \texttt{iptables} (see \texttt{firewall\_rules.sh}), tested with a local HTTP service on port 8080 and three simulated source subnets (staff, guest, external).

\subsection{Rules Summary}
\begin{itemize}
  \item Block guest subnet (192.168.20.0/24) $\rightarrow$ service port
  \item Allow staff subnet (192.168.10.0/24) $\rightarrow$ service port
  \item Drop all other inbound traffic to that port
\end{itemize}

\section{Conclusion}
The measures implemented -- network segmentation via firewall rules, authenticated symmetric encryption, and SHA-256 integrity verification -- address the vulnerabilities identified in the risk assessment. Testing confirmed that staff access is permitted while guest and external access to the protected service are correctly blocked, and that the encryption toolkit correctly encrypts, decrypts, and detects tampering.
